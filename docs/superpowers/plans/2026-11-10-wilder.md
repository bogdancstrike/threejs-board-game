# Wilder Implementation Plan

> **For agentic workers:** Execute inline in this session, as authorized by the user's implementation request. Track completion below.

**Goal:** Build a complete browser-based Three.js fantasy board adventure from the three supplied design documents.

**Architecture:** Deterministic 93-tile board data and pure game rules are independent of rendering. Modular world builders create a seeded miniature floating island. A DOM interface controls a Three.js viewport and character preview, with locally persisted progress.

**Tech Stack:** TypeScript, Vite, Three.js WebGLRenderer, OrbitControls, EffectComposer, Vitest, Playwright.

There is no pre-existing application or production character art to preserve. All twelve roster entries will use explicitly disclosed prototype figurines. GLB assets may replace them through a documented registry.

### Task 1: Rules and board
- [x] Create `src/game/data.ts` for the roster, regions, seeded 93-position route, and tile meanings.
- [x] Create `src/game/engine.ts` for dice movement, turn handling, mystery choices, victory, and save validation.
- [x] Create `tests/engine.test.ts` to verify route consistency, movement bounds, effects, and multiplayer turns. Run `npm test`.

### Task 2: Floating world
- [x] Create `src/world/assets.ts` for shared geometries/materials, scenery and prototype character builders.
- [x] Create `src/world/world.ts` for terraced terrain, protected path, castle, village, portal, vegetation, bridges, rivers and waterfalls.
- [x] Create `src/world/scene.ts` for camera controls, lighting, quality presets, movement, particles, selection and preview.

### Task 3: Playable interface
- [x] Create `src/main.ts` and `src/style.css` for responsive expedition UI, dice, mystery choices, journal, settings, character gallery and help.
- [x] Connect solo and local 2–4 player games, restart, local saves, camera tools, mute and keyboard controls.

### Task 4: Verification and handoff
- [x] Run `npm run build` and `npm test`.
- [x] Use Playwright to inspect the actual rendered desktop/mobile game, exercise character selection and turns, and check console errors.
- [x] Document launch commands, controls, rules, implementation coverage and production-asset limitations in `README.md` and `docs/ASSETS.md`.

## Accepted scope extensions

- The map occupies the full viewport below a slim header (over 90% of desktop screen height). Journey details are a drawer.
- Ten themed worlds include the original Dragonkind dragon academy setting inspired by Fourth Wing.
- The character selector includes previous/next, selection, orbit/zoom, body views, aura selection and motion controls.
- Supplied local models are integrated with attribution. Rigged sources and approximate generated rigs support procedural locomotion and waiting actions.
- Terrain-colored weathered route stones sit low in the surface with moss, rocks and small vegetation at selected tile edges.
- Vite stays available on localhost:7777 with hot reload throughout implementation.
